# TGFX AOT Shader 坐标依赖分析：为什么某些效果能预编译，某些不能

本文逐一分析 TGFX 当前受支持 Shader 的坐标依赖关系，回答“为什么这类效果能提前编译，那类不能”。核心判断不是简单的“输出像素只依赖同一坐标输入”，而是：

> **输出像素要么只依赖同一坐标输入，要么依赖一个被严格限定的、可提前枚举的坐标变换契约。凡是依赖不可枚举的坐标关系、邻居像素或目标像素的效果，当前都无法预编译。**

每个 Shader 都从五个维度分析：坐标依赖、资源接口、是否逐像素、能否提前枚举、为什么成立或失败。

---

## 1. TextureFillShader：逐像素纹理采样，坐标关系完全可枚举

### 坐标依赖

输出像素 `P(x, y)` 的颜色：

```glsl
color = texture(TextureSampler_0, transformedCoord(x, y));
```

`transformedCoord` 由绘制矩阵决定，构建期可以完整枚举其形式（平移、缩放、旋转、仿射）。

### 资源接口

- 固定 1 个主纹理；
- 可选 1 个设备遮罩；
- 目标读取方式 3 种（无、双源、读取帧缓冲）。

### 是否逐像素

是。输出只依赖同一坐标。

### 能否提前枚举

能。坐标变换由矩阵决定，构建期可以枚举；纹理对象是运行时绑定，不影响代码结构。

### 为什么成立

- 输出只依赖同一坐标；
- 资源接口有限；
- 坐标变换可枚举；
- 无邻居依赖、无目标读取。

### 边界

- 不能加入需要邻居采样的效果；
- 不能加入需要读取目标颜色的混合；
- YUV 纹理需要额外平面和坐标转换，不能混入普通链。

---

## 2. UnifiedGradientShader：坐标解析渐变，坐标关系完全可枚举

### 坐标依赖

输出像素 `P(x, y)` 的颜色由坐标在渐变几何中的位置决定：

```glsl
float t = computeGradientPosition(x, y, gradientParams);
color = evaluateGradient(t);
```

`computeGradientPosition` 由渐变类型（线性、径向、圆锥、钻石）决定，每种都有固定公式。

### 资源接口

- 无纹理或一个查找表纹理；
- 最多一个渐变源；
- 混合方式固定。

### 是否逐像素

是。输出只依赖同一坐标和渐变几何参数。

### 能否提前枚举

能。四种渐变类型已枚举，参数运行时上传。

### 为什么成立

- 坐标关系由解析公式决定；
- 无纹理或固定查找表；
- 无邻居依赖；
- 无目标读取。

### 边界

- 不能使用任意渐变函数；
- 查找表渐变至多与一个纹理源共存；
- 不能加入需要邻居采样的模糊渐变。

---

## 3. AtlasTextFillShader：图集纹理逐像素读取，坐标关系完全可枚举

### 坐标依赖

输出像素 `P(x, y)` 的颜色由当前字符在图集中的位置决定：

```glsl
vec2 atlasCoord = glyphPosition + localOffset(x, y);
color = texture(AtlasTexture, atlasCoord);
```

`glyphPosition` 由文本布局决定，构建期可以枚举；`localOffset` 由当前像素在字形内的相对位置决定。

### 资源接口

- 固定 1 个图集纹理；
- 覆盖叶在片元阶段注入；
- 混合方式固定。

### 是否逐像素

是。输出只依赖同一坐标和图集位置。

### 能否提前枚举

能。图集布局构建期已知，字符位置运行时上传。

### 为什么成立

- 输出只依赖同一坐标；
- 资源接口固定；
- 坐标关系可枚举；
- 无邻居依赖。

### 边界

- 不能使用动态生成的任意图集格式；
- 不能加入需要邻居采样的文本阴影或模糊；
- 图集必须满足标准格式。

---

## 4. PerlinNoiseFillShader：程序化噪声逐像素计算，坐标关系完全可枚举

### 坐标依赖

输出像素 `P(x, y)` 的颜色由程序化噪声函数决定：

```glsl
float noise = perlinNoise(x, y, frequency, seed, octaves);
color = mapNoiseToColor(noise);
```

噪声函数由频率、种子、八度决定，构建期可以枚举其形式。

### 资源接口

- 无纹理；
- 最多 3 个后续颜色操作；
- 混合方式固定。

### 是否逐像素

是。输出只依赖同一坐标和噪声参数。

### 能否提前枚举

能。噪声函数形式固定，参数运行时上传。

### 为什么成立

- 输出只依赖同一坐标；
- 无纹理依赖；
- 坐标关系可枚举；
- 无邻居依赖。

### 边界

- 噪声后最多 3 个颜色操作；
- 不能加入需要邻居采样的模糊或阴影；
- 不能加入需要读取目标颜色的混合。

---

## 5. GaussianBlur1DShader：邻域采样，但坐标变换被严格限定

### 坐标依赖

输出像素 `P(x, y)` 的颜色依赖周围半径 `r` 内的多个输入像素：

```glsl
color = 0;
for (int i = -r; i <= r; ++i) {
  color += weight[i] * texture(Texture, x + i, y);
}
```

这是邻域采样，不是逐像素。

### 资源接口

- 固定 1 个纹理；
- 模糊半径和权重由参数决定；
- 混合方式固定。

### 是否逐像素

否。输出依赖邻居像素。

### 能否提前枚举

能，但**坐标变换被严格限定**：

- 只允许一维模糊（X 或 Y）；
- 半径和权重由参数决定，但采样模式固定；
- 不允许任意二维卷积或自定义核。

### 为什么成立

- 坐标依赖虽然超出单像素，但被严格限定为固定的一维核；
- 构建期可以枚举所有可能的半径和权重组合；
- 资源接口固定；
- 不读取目标颜色。

### 边界

- 只允许一维模糊；
- 不能任意二维卷积；
- 不能加入其他邻居效果；
- 参数超出契约范围会拒绝。

---

## 6. YUVTextureFillShader：多平面采样，但平面关系被严格限定

### 坐标依赖

输出像素 `P(x, y)` 的颜色由 Y、U、V 三个平面共同决定：

```glsl
float y = texture(YTexture, x, y).r;
float u = texture(UTexture, x, y).r;
float v = texture(VTexture, x, y).r;
color = yuvToRgb(y, u, v);
```

### 资源接口

- 固定 3 个纹理（Y、U、V）；
- 采样坐标相同；
- 混合方式固定。

### 是否逐像素

是。输出只依赖同一坐标，但需要三个纹理。

### 能否提前枚举

能。YUV 格式（I420、NV12 等）已枚举，平面数量固定。

### 为什么成立

- 输出只依赖同一坐标；
- 平面数量固定；
- 坐标关系可枚举；
- 无邻居依赖。

### 边界

- 不能混入普通 RGBA 颜色链；
- 必须使用专用 YUV 路径；
- 不能加入需要邻居采样的效果。

---

## 7. PointwiseTailShader：线性颜色链逐像素执行，容量被严格限定

### 坐标依赖

输出像素 `P(x, y)` 的颜色由一系列逐像素操作决定：

```glsl
vec4 color = texture(TextureSampler_0, coord);
color = applyColorMatrix(color, matrix);
color = applyAlphaThreshold(color, threshold);
```

### 资源接口

- 固定 1 个主纹理；
- 可选设备遮罩；
- 最多 2 个颜色操作；
- 混合方式固定。

### 是否逐像素

是。输出只依赖同一坐标。

### 能否提前枚举

能。操作类型已枚举（ColorMatrix、Luma、AlphaThreshold、ColorSpaceXform），容量固定为 2。

### 为什么成立

- 输出只依赖同一坐标；
- 资源接口固定；
- 操作类型有限；
- 无邻居依赖。

### 边界

- 最多 2 个颜色操作；
- 超过则自动拆成多个 Pass；
- 不能加入邻居效果；
- 不能加入需要读取目标颜色的混合。

---

## 8. PointwiseChainShader：分支颜色关系逐像素执行，容量被严格限定

### 坐标依赖

输出像素 `P(x, y)` 的颜色由两个或多个颜色源经混合得到：

```glsl
vec4 colorA = texture(TextureA, coord);
vec4 colorB = texture(TextureB, coord);
vec4 result = blend(colorA, colorB, blendMode);
result = applyColorMatrix(result, matrix);
```

### 资源接口

- 最多 4 个真实纹理源；
- 最多 16 条操作记录；
- 混合方式固定。

### 是否逐像素

是。输出只依赖同一坐标。

### 能否提前枚举

能。操作类型、纹理数量、记录数量都有固定上限。

### 为什么成立

- 输出只依赖同一坐标；
- 资源接口有明确上限；
- 操作类型有限；
- 无邻居依赖。

### 边界

- 最多 4 个真实纹理源；
- 最多 16 条操作记录；
- 不能加入邻居效果；
- 不能加入需要读取目标颜色的混合；
- 不能自动拆成多 Pass。

---

## 9. 为什么邻居效果不能预编译

邻居效果（Blur、DropShadow、Convolution、马赛克）的输出像素依赖周围多个输入像素：

```glsl
color = Σ weight[i] * texture(Texture, x + dx[i], y + dy[i]);
```

问题：

- `dx[i], dy[i]` 可以是任意值，构建期无法枚举所有可能；
- 需要多次采样，资源接口无法固定；
- 可能需要读取目标颜色；
- 中间结果精度要求高，无法用 RGBA8 中间纹理安全传递。

除非坐标变换被严格限定（如 GaussianBlur1DShader），否则无法提前枚举。

---

## 10. 为什么需要读取目标颜色的混合不能预编译

某些混合模式需要读取帧缓冲已有内容：

```glsl
color = blend(src, dst);
```

问题：

- `dst` 在运行时才知道，构建期无法确定；
- 拆成多个 Pass 后，中间 Pass 的目标已经是中间纹理，不是最终目标；
- 无法保证语义一致。

---

## 11. 为什么 RuntimeEffect 不能预编译

RuntimeEffect 允许用户传入任意 GLSL 源码：

```glsl
vec4 myCustomEffect(vec2 coord, sampler2D tex, float param) {
  // 任意逻辑
}
```

问题：

- 构建期无法预知源码形态；
- 无法枚举资源接口；
- 无法验证坐标依赖关系；
- 无法保证逐像素或固定契约。

---

## 12. 最终判断规则

一个效果能被预编译，当且仅当：

1. **输出像素只依赖同一坐标输入**，或者依赖一个**被严格限定的、可提前枚举的坐标变换契约**；
2. 资源接口（纹理数量、绑定、混合方式）在构建期可以完全枚举；
3. 不需要读取目标颜色；
4. 中间结果可以用 RGBA8 或更高精度格式安全传递（如果需要拆 Pass）。

不满足其中任何一条，当前都必须运行时编译。

---

## 13. 用户如何调整实现以达到相同视觉效果

| 原实现 | 为什么不能 AOT | 调整方式 |
| --- | --- | --- |
| 模糊后调色 | 模糊是邻居效果 | 先模糊到离屏纹理，再对离屏纹理调色 |
| 多纹理混合超过 4 张 | 资源上限 | 把其中稳定的两层先离线合成一张 |
| 需要读取目标颜色的混合 | 无法确定 dst | 改用 Porter-Duff 模式，或先画到离屏再合成 |
| RuntimeEffect | 无法枚举 | 改写为枚举内操作，或离线烘焙成纹理 |
| 高精度调色链 | RGBA8 量化 | 合并到同一 Pass，或接受运行时编译 |

---

## 14. 一句话总结

> **AOT 能预编译的是“坐标关系可以枚举、资源接口固定、不读目标像素”的效果；邻居采样、任意自定义源码、需要读目标的效果，当前都必须运行时编译。**
